Hermes 部署与运维

本地部署（已完成）

环境

  • 位置：/Users/nj/Documents/企业数字员工/hermes/
  • Python：3.11.11（uv 虚拟环境）
  • 依赖：102 个 Python 包，已通过 uv.lock 哈希校验
  • CLI：hermes 命令可用（~/.local/bin/hermes）
  • 技能：90 个内置技能已同步到 ~/.hermes/skills/

首次启动

cd /Users/nj/Documents/企业数字员工/hermes

source venv/bin/activate


hermes setup       # 配置 API Key


hermes             # 启动聊天

.env 配置

需要配置至少一个 LLM 提供商的 API Key：

  • OPENROUTER_API_KEY= — 推荐，支持 200+ 模型
  • OPENAI_API_KEY=
  • ANTHROPIC_API_KEY=
  • DEEPSEEK_API_KEY=

配置文件位置：/Users/nj/Documents/企业数字员工/hermes/.env

Docker 部署

项目自带 Dockerfile 和 docker-compose.yml：

cd /Users/nj/Documents/企业数字员工/hermes

docker compose up -d

Serverless 部署

Daytona

hermes config set terminal.backend daytona

hermes config set terminal.daytona.api_key your_key

Modal

hermes config set terminal.backend modal

特点：环境空闲时休眠，按需唤醒，几乎零成本。

消息网关部署

网关是一个后台进程，同时对接多个消息平台：

hermes gateway install      # 安装为后台服务

hermes gateway              # 前台运行

支持的平台：

  • Telegram（需 Bot Token）
  • Discord（需 Bot Token）
  • Slack（需 App Token）
  • WhatsApp（需 API Key）
  • Signal（需本地 Signal CLI）

配置方式：hermes setup 交互式配置，或直接编辑 .env。

Cron 定时任务

设置无人值守的自动化任务：

hermes cron add

按提示输入：cron 表达式 + 任务描述 + 投递平台

示例：

每天早9点发送行业日报 → 0 9   * → Telegram

每周一审计数据 → 0 8   1 → Email


每月备份 → 0 2 1   → Discord

安全配置

  • 命令审批：危险命令需要确认（--yolo 跳过）
  • DM 配对：消息平台需要配对码授权
  • 容器隔离：Docker/SSH 后端隔离执行
  • TIRITH：安全策略引擎，可自定义规则
  • OSV：依赖漏洞扫描（hermes security）
hermes doctor          # 检查配置是否安全

hermes security        # 扫描供应链漏洞


hermes pairing         # 管理配对码

监控与维护

hermes status          # 整体状态

hermes doctor          # 配置诊断


hermes logs -f         # 实时日志


hermes backup          # 备份数据


hermes update          # 更新版本


hermes sessions prune  # 清理旧会话（释放空间）
